## Answers
**(a) Can we register a new task?** Yes, by editing/adding files; there is no plugin API. The public evaluator is a closed
catalog: `x2real_eval.py` only runs cases listed in a board's leaderboard CSV (`load_eval_cases`, x2real_eval.py:271;
unknown env rejected at :999), boards come from `manaenv/defination/x2real/task/boards.yaml` (:69, `suite:` per board),
and the suite YAML holds `scene_orders / task_orders / assembly_orders / rollout` (x2real.yaml:117,171,223,1173).
`--check` / `--asset-check` hardcode 5 boards / 73 cases (x2real_eval.py:82, :963) and will fail or ignore us: do not use them.
Our additions (all generated by `qr_sort_task/build_task.py`): `defination/labelloop.yaml` (includes `x2real.yaml`, replaces the four
lists; robots/pipeline/output inherited, expand_includes: reflective_translator.py:53), `labelloop/scene/caseN.yaml`,
`labelloop/task/{stage_base,caseN_dag}.yaml`, `x2real/task/labelloop_leaderboard.csv`, one appended board `labelloop_tabletop`
in boards.yaml, plus `manaenv/assets/objects/labelloop_qr_sort.py` (copied). Env names must be `artixon_arm6a_G_<task>_id_env`
(_x2real_suite.py:201). Rollout budgets must equal the board's (x2real_eval.py:329): 40 episodes, 4 envs, CSV timeout.

**(b) Closest built-in host (fallback if (a) is blocked):** `pick_by_attribute` (x2real/scene/language_reasoning/pick_by_attribute/vnext.yaml
+ task/.../vnext_dag.yaml: objects from a pool, one basket, success `attribute_targets_in_basket`, terminations.py:5465) or
`classify_objects_color` (4 objects -> 4 colour targets, `classified_object_on_color_target`, terminations.py:6275, with blue/orange
as two of the colours). Both swap objects via asset pool JSON (`assets/manipulation/*.json`, not in the repo) or `material_variants`.

**(c) 100x100x50 mm textured box.** X2Real has no primitive spawner in scene YAML: every object is a USD `LibraryObject`
registered with `@register_asset` (assets/objects/object_library.py:1; fixtures like move_bottle_to_bin.py:1 are preloaded by
`background.asset_module`, manaenv_scene_bridge.py:30). Textures use OmniPBR `inputs:diffuse_texture` (object_library.py:257) and
per-episode texture swaps use `objects[].material_variants` + `runtime_sample.targets.materials` (image_puzzle/vnext.yaml:39,
runtime_compile.py:1304; randomizer supports OmniPBR and UsdPreviewSurface, shader_io.py:33,117).
We author `box_*.usda` (cuboid mesh with UVs, one atlas = top face | labeled +Y side | kraft, `qr_sort_task/make_usd.py`) and
register one asset per code (`labelloop_box_a001`...). Per-code fixed asset, not texture swap, so the success term knows the zone.

**(d) Randomization.** Pose/yaw: scene `layout.groups.*` region (`ranges`, `yaws`, `jitter`, `min_spacing`) sampled each reset through
task `layout.runtime_sample.targets.placements` (pick_by_attribute/vnext.yaml:97-150). Materials: `runtime_sample.targets.materials`
(used for the table mat). Lighting: `scene.lighting.dome` + `runtime_sample.global.lighting` (parser.py:2233, runtime_compile.py:769) and
event `randomize_scene_lighting` (events.py:484) exist but **no public case uses them [UNVERIFIED]**; not wired in our cases yet.
`surface_material_pool` (table material) is hard-wired to a `SchemaVNextInsertedTable` prim (runtime_compile.py:1502), so we use a thin
mat object instead. Mid-episode human events: task `event_component` accepts `mode: interval`, `interval_range_s`, `is_global_time`
(event_component.py:54-65; example pick_and_place_on_turnable/vnext_dag.yaml:42). Our `disturb` event (move a box / teleport a parked box onto
the table) uses that: feasible, **[UNVERIFIED]**; limit: one-shot-ness comes from a long interval, no true "add a new object".

**(e) Cameras.** Wrist cams (left/right): X2Robot 5756 fisheye, **640x480@30**, equidistant, f = 255.8 px/rad, near clip 0.01 m
(sensors/x2robot_5756_fisheye_camera.py:28-48; ex001_6r.py:342-364). Head cam: 1280x720 pinhole (ex001_6r.py:365-381; suite
streams it at 960x540, x2real.yaml:28-36). The policy client sends 640x480 (policy/x2real_ps@v1.0.0.yaml:30). A 55 mm QR symbol
(25 modules, v2-H) straight-on spans 2*255.8*atan(27.5/d) px: d=10 cm 137 px (5.5 px/module), 15 cm 93 px (3.7), 20 cm 70 px (2.8, marginal).
So read at 10-15 cm; off-axis the fisheye compresses it further. Wrist cam is on `*_arm_gripper_camera_color_frame` (child of the EE).

## Frames and home pose
Policy wire poses are in the Isaac articulation-root frame, relative to the EE pose captured at reset (`wire_pose_reference: init_ee_pose`,
embodiments/policy_space/EX0016REmbodiment.yaml:60; action_transforms.py:431, embodiment_obs.py:391). `base_link` mode (absolute root-frame
poses, no home pose needed) exists in the transform but the YAML field is the only switch **[UNVERIFIED that a server may select it]**.
EX001-6R G default joints are all 0 (no `joint_pos` in `init_state`, ex001_6r.py:261; none in robot yaml), so home FK is at q=0.
FK of `*_arm_gripper_base_link` in URDF `base_platform_link` (the URDF has no `base_link`): left [0.1185, 0.2660, 0.1810], right [0.1185, -0.2660, 0.1810], rpy 0.
`ex001_6r.py:126` quotes a sim right-arm EE of (0.1185, -0.29, 0.211): x matches, y/z differ by (-0.024, +0.030), so the Isaac root is probably offset
from `base_platform_link` by about that. No quanta/WALLX conversion exists anywhere in X2Real (grepped quanta, arm_base, wallx, master_ee).

## Linux steps
```bash
source ./install.sh                                  # in X2; then fetch x2real-assets (see X2 README) and
export MANAENV_ASSET_ROOT=/path/x2real-assets X2REAL_ROOT=/path/x2real
cd LabelLoop && python sim/make_qr_boxes.py --out sim/assets
python sim/qr_sort_task/make_usd.py --labels sim/assets --out $MANAENV_ASSET_ROOT/labelloop
cp sim/qr_sort_task/labelloop_qr_sort.py $X2REAL_ROOT/manaenv/assets/objects/
python sim/qr_sort_task/build_task.py --x2real $X2REAL_ROOT
cd $X2REAL_ROOT && python manaenv/scripts/x2real_eval.py --board labelloop_tabletop --list   # 6 cases, else fix YAML
# policy server up (3rd/policy_space template or LabelLoop server on :8001), then from LabelLoop:
python scripts/run_sim_case.py --case 1 --runs 1 --viz kit
```
First run: look at it in Kit. Tune (all at the top of `build_task.py`): bin/box/mat positions (`SURF_TO_ENV`, `TABLE_Z`, ranges are
guesses copied from other scenes), box UV orientation, bin size, mass/friction. Then `--viz none --runs N` per case; results:
`$X2REAL_ROOT/outputs/x2real_eval/labelloop/benchmark/<env>/{evaluation_report.jsonl,videos/combined/episode_*.mp4}`.
Success = every labelled box in its bin (A blue, B orange), decoys in neither, then arms home (`boxes_sorted`, labelloop_qr_sort.py).

**QR gate** (`sim/qr_gate.py`: box pinned label-towards-camera at distance d in front of the right wrist camera, label shifted up 0.45*d in the image because the
gripper fingers fill the lower half of the wrist view; 10 frames each; zxing-cpp on raw RGB; label 55 mm + 8 mm quiet zone):
