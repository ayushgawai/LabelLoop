# WALLX debug review

1. **Grasp geometry and bin confusion.** A 97.5 mm jaw cannot span IQBAR’s 102 mm flat width. The upright, front-to-back setup delivered 5/6 with the idle arm held. Stage one parcel upright with its graspable faces accessible and clear of the bins. Replace the shoeboxes with visually distinct, rigidly fixed, low-sided colored trays. The training props are unknown. [Trial observations](../../docs/reviews/wallx_debug_packet.md)
2. **Instruction and termination.** Use one organizer-style instruction (`put the box into the blue bin`) with one obvious parcel. This path sends arm names only as instruction text, and the rotation prompt yielded a drop. Select the idle arm in the relay for single-arm stages, route reorientation through a dedicated scripted stage, and switch to a hold reply as soon as placement is verified. [Relay routing](../../labelloop/robots/event_server.py#L177)
3. **History continuity.** Set top-level `session_id` to a unique per-robot episode ID and `use_history: true` explicitly (metadata already defaults to true). Set `reset_history: true` on the first inference and after actual motion discontinuities, such as scripted repositioning. Preserve history through wording-only changes. Centralize reconnect/retry handling so an uncertain replay gets one deliberate reset instead of an implicit resend followed by a separate reset path. Omitted-ID behavior is unknown, and four active robots only establishes concurrency. [Relay reset](../../labelloop/robots/event_server.py#L193) · [Client resend](../../labelloop/wallx_client.py#L89)
4. **Executed actions can diverge from predictions.** The hold and gripper clamps edit replies after inference, so cached history may reflect motion the robot never executed. Turn off `--open-wide` for the baseline. If the idle-arm hold is required, log raw and sent chunks with next measured state, and compare `use_history: false` against true before enabling history with that hold. [Reply edits](../../labelloop/robots/event_server.py#L210)
5. **Slow sync loop.** At ~1.4 s per call, feedback arrives slower than the ~1.08 s represented by 32 rows. Measure capture-to-dispatch latency and executed rows, then reduce that delay in sync mode. The RTC-named preset does not activate RTC on this path. The relay rejects its request fields, and four RTC rows cover only ~135 ms. Keep `embodiment` and measured state as supplied by the organizer client, leave deprecated `normalization` omitted, and leave `control_context` unset until its trained delays or offset are calibrated. [Relay validation](../../labelloop/robots/event_server.py#L21) · [RTC contract](../../docs/research/client/rtc.txt#L12)

**First experiment.** Alternate 10 matched pairs of trials with shoeboxes versus colored trays, both fixed at the same target positions. Keep the upright IQBAR pose, starting arm states, idle-arm hold, sync settings, and `put the box into the blue bin` constant. Start each trial with cleared history. Score first object approached, bin contact before parcel pickup, and successful delivery. Stop each trial at verified placement or a fixed timeout.
